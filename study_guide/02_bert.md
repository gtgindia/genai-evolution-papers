# BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding — Devlin, Chang, Lee, Toutanova, Google AI Language, 2018 — arXiv:1810.04805

## The story in one paragraph

This paper shows how to pre-train one general language model on unlabeled text and then quickly adapt it to many different language tasks with only a small extra layer. Earlier pre-trained models could only read left to right, which meant they missed useful clues from the right side, especially for tasks like question answering where the answer depends on both sides of a word. The authors invent two new pre-training games called masked language modeling and next sentence prediction, which force a deep Transformer encoder to learn from both left and right context at every layer. After pre-training on BooksCorpus and English Wikipedia, the same model is fine-tuned end to end and sets new records on eleven tasks including GLUE, SQuAD, and SWAG, often with only one hour of fine-tuning. The approach is conceptually simple and empirically very powerful.

## What problem was hurting before this paper

Before BERT, there were two main ways to reuse pre-trained language knowledge, and both were limited. The feature-based approach like ELMo extracted context-sensitive word vectors from left-to-right and right-to-left language models and plugged them into task-specific architectures as extra features. This helped, but the pre-trained parts were shallow combinations of two separate one-directional models, not a deeply bidirectional model. The fine-tuning approach like OpenAI GPT pre-trained a Transformer but constrained every token to attend only to previous tokens, because standard language modeling predicts the next word and would cheat if it could see the future. This left-to-right restriction is suboptimal for sentence-level tasks and can be very harmful for token-level tasks like question answering, where identifying an answer span crucially needs right-side context.

In practice this meant researchers still needed heavily engineered task-specific architectures for each benchmark, and results lagged far behind what deep bidirectional understanding could offer. The paper argues that we need a way to pre-train deep bidirectional representations without letting the model trivially see the word it is trying to predict.

## The core idea, explained simply (with an analogy)

The core idea is to train with fill-in-the-blank games instead of next-word prediction, so the model must use both sides to guess the missing pieces. First, randomly hide some words with a mask token and ask the model to recover them from surrounding context. Second, show two sentences and ask whether the second one truly follows the first in the original document.

A helpful analogy is studying for exams with a smart friend. The old left-to-right student could only cover the right side of the page and guess what comes next, so they never learned to use future clues. The BERT student plays a cloze test where the teacher blanks out words anywhere in the paragraph, so they must read the whole paragraph left and right to fill the gaps. They also practice a coherence game where they read two paragraphs and decide if the second really comes next, which teaches them about relationships between sentences like entailment and question-answer matching. After months of these games on a huge library, the student can quickly learn any new exam format with just a few examples.

## How it actually works (step by step: architecture, training objective, inference — explain each piece in words; if there is a famous equation like scaled dot-product attention, explain what each part means in plain language)

The architecture is a multi-layer bidirectional Transformer encoder based directly on the original Transformer from Attention Is All You Need, without the causal mask. The authors denote layers as L, hidden size as H, and attention heads as A. BERT base uses twelve layers, hidden size seven hundred and sixty-eight, twelve heads, and one hundred and ten million parameters, chosen to match OpenAI GPT in size for fair comparison. BERT large uses twenty-four layers, hidden size one thousand and twenty-four, sixteen heads, and three hundred and forty million parameters. The feed-forward filter size is always four times the hidden size, so three thousand and seventy-two for base and four thousand and ninety-six for large. The activation is GELU rather than ReLU, following GPT.

The input representation is designed to handle both single sentences and sentence pairs in one sequence. Every sequence starts with a special classification token called CLS, whose final hidden state becomes the aggregate representation for classification tasks. Sentence pairs are separated by a special separator token called SEP. Each token gets three embeddings that are added together, namely token embeddings from a thirty thousand WordPiece vocabulary, segment embeddings that say whether the token belongs to sentence A or sentence B, and position embeddings for word order. A sentence here means any contiguous span of text, not necessarily a linguistic sentence.

Pre-training task number one is masked language modeling. The problem with deep bidirectional training is that if every word can see both sides in multiple layers, it can indirectly see itself and trivially predict itself. The solution is to mask fifteen percent of WordPiece tokens at random in each sequence and only predict those masked positions with cross-entropy loss over the vocabulary. Unlike denoising auto-encoders that reconstruct the whole input, BERT only predicts the masked words, which means it needs more pre-training steps but gains much richer representations. To reduce the mismatch that the mask token never appears during fine-tuning, the authors use an eighty ten ten rule. For each chosen position, eighty percent of the time they replace it with the mask token, ten percent of the time with a random token, and ten percent of the time they leave it unchanged but still ask the model to predict it. This forces the model to keep a good representation for every token, because it never knows which words will be queried or corrupted. A tiny example from the appendix is my dog is hairy becoming my dog is mask, my dog is apple, or my dog is hairy, with the model asked to recover hairy.

Pre-training task number two is next sentence prediction. For each training example, fifty percent of the time sentence B is the actual next sentence after A labeled as IsNext, and fifty percent of the time it is a random sentence from the corpus labeled as NotNext. The final hidden vector of the CLS token is used for this binary classification. The final model reaches ninety-seven to ninety-eight percent accuracy on this task. Although simple, this task teaches sentence relationships that pure language modeling misses, and ablations show it strongly helps question answering and natural language inference.

Pre-training data is BooksCorpus with eight hundred million words plus English Wikipedia with two thousand five hundred million words, totaling about three point three billion words. The authors stress using document-level corpora rather than shuffled sentences like the Billion Word Benchmark, so the model can see long contiguous sequences for the next sentence task. Sequences are sampled so combined length is at most five hundred and twelve tokens. Training uses batch size two hundred and fifty-six sequences, which equals one hundred and twenty-eight thousand tokens per batch, for one million steps or about forty epochs. The optimizer is Adam with learning rate one times ten to the minus four, beta one zero point nine, beta two zero point nine nine nine, weight decay zero point zero one, warmup over ten thousand steps, linear decay, and dropout zero point one. To save time, ninety percent of steps use sequence length one hundred and twenty-eight and the last ten percent use five hundred and twelve to learn positional embeddings. BERT base trained on four Cloud TPUs in pod configuration with sixteen chips total, and BERT large trained on sixteen Cloud TPUs with sixty-four chips total, each taking four days.

Fine-tuning is straightforward and inexpensive. The same pre-trained architecture is reused with only a new output layer, and all parameters are fine-tuned end to end. For GLUE classification, the CLS vector C is multiplied by a new classification matrix W and passed through softmax, with standard classification loss. The model is trained with batch size sixteen or thirty-two, learning rates five, four, three, or two times ten to the minus five, for two, three, or four epochs, chosen on the development set. Most results can be replicated in at most one hour on a single Cloud TPU. For SQuAD question answering, the question uses A embeddings and the passage uses B embeddings packed as one sequence, with new start and end vectors that dot-product with every token representation to score answer spans. For SWAG commonsense, four concatenated sentence pairs are scored with a dot product against the CLS vector and normalized with softmax. For NER tagging, the first sub-token of each word feeds a token classifier.

## Key results and numbers from the paper (with the actual scores/tables described in words)

On GLUE, both BERT base and BERT large beat all prior systems on all tasks. BERT base reaches eighty-four point six on MNLI matched and eighty-three point four on mismatched, seventy-one point two on QQP, ninety point five on QNLI, ninety-three point five on SST-2, fifty-two point one on CoLA, eighty-five point eight on STS-B, eighty-eight point nine on MRPC, and sixty-six point four on RTE, for an average of seventy-nine point six compared to seventy-five point one for OpenAI GPT and seventy-four point zero for prior state of the art. BERT large reaches eighty-six point seven on MNLI matched and eighty-five point nine on mismatched, seventy-two point one on QQP, ninety-two point seven on QNLI, ninety-four point nine on SST-2, sixty point five on CoLA, eighty-six point five on STS-B, eighty-nine point three on MRPC, and seventy point one on RTE, for an average of eighty-two point one. On the official leaderboard, BERT large scores eighty point five versus seventy-two point eight for GPT. The MNLI gain of four point six points is especially notable as the largest and most reported task.

On SQuAD version one point one with one hundred thousand crowd-sourced question-answer pairs, BERT large single model reaches eighty-four point one exact match and ninety point nine F1 on development data. With seven-model ensembling it reaches eighty-five point eight exact match and ninety-one point eight F1. With extra fine-tuning on TriviaQA first, the ensemble reaches eighty-seven point four exact match and ninety-three point two F1 on the hidden test set, beating the top leaderboard ensemble by one point five F1, with the single model alone beating the top ensemble. On SQuAD version two point zero with unanswerable questions, BERT large single model reaches seventy-eight point seven exact match and eighty-one point nine F1 on development and eighty point zero exact match and eighty-three point one F1 on test, beating the prior best by five point one F1. The trick for no-answer cases is to treat CLS as the answer span and only predict a non-null answer when its score exceeds the null score by a threshold tuned on development data.

On SWAG grounded commonsense with one hundred and thirteen thousand sentence completions, BERT base reaches eighty-one point six and BERT large reaches eighty-six point six on development and eighty-six point three on test, beating ESIM plus ELMo at fifty-nine point two and OpenAI GPT at seventy-eight point zero by large margins, approaching expert human performance at eighty-five to eighty-eight percent.

Ablations prove both innovations matter. Removing next sentence prediction hurts QNLI, MNLI, and SQuAD significantly. Training left-to-right without next sentence prediction like GPT drops MRPC from eighty-six point seven to seventy-seven point five and SQuAD from eighty-eight point five to seventy-seven point eight. Adding a randomly initialized BiLSTM on top helps SQuAD to eighty-four point nine but still falls far short of bidirectional pre-training and hurts GLUE. Larger models strictly help even on tiny datasets like MRPC with only three thousand six hundred examples, with masked language model perplexity falling from five point eight four to three point two three as size grows. The feature-based test on CoNLL 2003 NER shows concatenating the top four hidden layers plus a BiLSTM reaches ninety-six point one F1, only zero point three behind full fine-tuning at ninety-six point six, proving BERT works well both ways.

## Why this paper matters (what later work it unlocked — name the specific later papers among the 15 where relevant)

BERT proved that one pre-trained bidirectional Transformer can replace many task-specific architectures and ignited the pre-train then fine-tune era. It directly enables the GPT-3 paper, which is number three, as a point of comparison and as inspiration for scaling in the other direction with left-to-right decoders. The retrieval-augmented generation paper, which is number four, builds retrievers and generators on BERT-style encoders. The CLIP paper, which is number six, uses BERT-like text Transformers alongside vision Transformers. The InstructGPT paper, which is number eight, starts from GPT-3 style decoders but uses BERT-style reward models and evaluation ideas from this era. The Chinchilla paper, which is number ten, refines scaling lessons that BERT ablations began. The LoRA paper, which is number eleven, the FlashAttention paper, which is number twelve, the LLaMA-2 paper, which is number thirteen, the DPO paper, which is number fourteen, and the DeepSeek-R1 paper, which is number fifteen, all inherit the Transformer encoder-decoder insights, the WordPiece tokenization, the CLS and SEP conventions, and the fine-tuning methodology that BERT standardized. Beyond the fifteen, BERT spawned RoBERTa, ALBERT, DistilBERT, BigBird, and the entire field of BERTology that probes what each layer learns, plus deployment in Google Search for English queries in October 2019 and for over seventy languages by December 2019.

## Honest limitations

The authors are clear that masked language modeling predicts only fifteen percent of tokens per batch, so it converges slower than left-to-right modeling and needs about one million steps, which took four days on large TPU pods. There is a pre-train fine-tune mismatch because mask tokens never appear at fine-tuning time, which the eighty ten ten trick mitigates but does not fully remove. Next sentence prediction is a coarse signal based on random negatives and later work showed it is weaker than originally thought. Fine-tuning of BERT large can be unstable on small datasets and requires several random restarts. The model is English only, limited to five hundred and twelve tokens, expensive to pre-train, and still needs labeled data for every downstream task, unlike later few-shot methods.

## Fun trivia and history (from your web search)

BERT is named after Bert from Sesame Street, continuing a playful Muppet naming tradition in language modeling. It began in 2017 with ELMo from the Allen Institute for AI, whose creators liked the whimsical Sesame Street flavor. Google researchers debuted BERT the next year explicitly acknowledging that debt to ELMo. Others joined the inside joke with BigBird for long sequences, ERNIE from Baidu, Kermit, Grover for detecting fake news, RoBERTa, and Rosita. OpenAI's GPT-2 was reportedly almost called Snuffleupagus but the name was dropped for not sounding serious enough.

BERT won Best Long Paper at NAACL 2019 in Minneapolis and became one of the most cited papers ever with well over one hundred thousand citations. Google open-sourced the code and pre-trained base and large checkpoints on GitHub, which let anyone fine-tune a state-of-the-art question answering model in about thirty minutes on a single Cloud TPU. That openness, plus rapid adoption in Google Search, turned BERT from a research paper into everyday infrastructure almost overnight.

## Key terms explained (glossary of 5-8 terms)

Bidirectional representations means word vectors that incorporate both left and right context at every layer, so the meaning of bank can use both river on the left and money on the right.

Masked language model means the pre-training task where random tokens are hidden and the model must predict the original vocabulary ids from context, inspired by the Cloze test from 1953.

Next sentence prediction means the auxiliary task where the model decides if sentence B truly follows sentence A or is random, which teaches relationships like entailment and question-answer pairing.

Fine-tuning means initializing a downstream model with pre-trained weights and then training all parameters end to end on labeled task data with a small new output layer.

Feature-based approach means freezing the pre-trained model, extracting its activations as extra features, and training a separate task-specific model on top, as ELMo did and as BERT also supports.

WordPiece embeddings means subword tokenization with a thirty thousand token vocabulary that splits rare words into pieces like play and ing, which handles open vocabulary gracefully.

CLS and SEP tokens means special symbols where CLS marks the start of every sequence and provides the aggregate representation for classification, while SEP separates sentences or question-passage pairs.

GLUE, SQuAD, and SWAG means popular benchmarks where GLUE tests general language understanding across nine tasks, SQuAD tests answer-span prediction from Wikipedia passages, and SWAG tests choosing the most plausible physical continuation.

## Connections (which earlier paper it builds on, which later paper builds on it)

BERT builds directly on Attention Is All You Need, which is number one, by using its Transformer encoder, multi-head self-attention, and tensor2tensor implementation. It builds on ELMo for contextual embeddings, on OpenAI GPT for Transformer fine-tuning, and on the Cloze task, sentence embedding work, and supervised transfer from natural language inference and translation.

Later, GPT-3, which is number three, contrasts itself with BERT by scaling left-to-right decoders and replacing fine-tuning with few-shot prompting. Retrieval-augmented generation, which is number four, CLIP, which is number six, InstructGPT, which is number eight, Chinchilla, which is number ten, LoRA, which is number eleven, FlashAttention, which is number twelve, LLaMA-2, which is number thirteen, DPO, which is number fourteen, and DeepSeek-R1, which is number fifteen, all build on BERT's proof that large-scale pre-training plus simple adaptation can dominate many benchmarks.
